# Security Policy

## Supported versions

Security fixes are prioritized for the latest stable release and the active development branch.

## Reporting a vulnerability

Please do not publish exploit details, private network data, credentials, or proof-of-concept code in a public issue.

Use GitHub's **Private vulnerability reporting** feature on this repository (Security → Advisories → Report a vulnerability) when it is enabled. If that option is unavailable, open a minimal public issue asking the maintainers for a private reporting channel; do not include technical details until a private channel is provided.

Include the affected version/commit, impact, reproducible high-level steps, and any suggested mitigation. Do not include real IP addresses, MAC addresses, device names, or other personal/network data.

## Project security commitments

- Network information is processed locally and is not sent to project-owned servers.
- Cleartext network traffic is prohibited.
- Release packages must be verified before installation.
- Security fixes and relevant changes are documented in the changelog.
