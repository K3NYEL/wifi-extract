# Contributing

## Workflow
1. Branch from `develop` using `feature/<short-name>` or `fix/<short-name>`.
2. Keep changes focused and avoid committing local SDK paths, signing keys, or generated build output.
3. Run an Android Gradle build before opening a pull request.
4. Open a pull request into `develop` and describe device/API limitations.

## Commit style
Use concise conventional prefixes: `feat:`, `fix:`, `docs:`, `build:`, `refactor:`, `test:`.

## UI direction
Use the project design tokens: near-black backgrounds, graphite surfaces, muted gray secondary text, and a restrained red accent. Prefer compact layouts, thin separators, and square or minimally rounded geometry. Avoid gradients, oversized cards, decorative glow, and emoji in product UI.
